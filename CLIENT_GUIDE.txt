IDS LAB SERVER - STUDENT CONNECTION GUIDE
=========================================

Use this guide after the administrator confirms your access is ready.
SSH is the recommended way to use the lab for daily work, running commands
and training models. The XFCE graphical desktop is always available through
X2Go when you need it; GUI access does not require a separate account.
Both methods use the same Linux account and run computation on the lab PC.
The server and your WireGuard connection must be online for either method.

1. INFORMATION FROM YOUR ADMINISTRATOR
--------------------------------------
Connect WireGuard first, then use SSH (recommended) or X2Go (GUI available anytime). The fixed GPU PC address is
10.8.0.100. Each student still needs their own VPN profile and Linux account
from the administrator before connecting.

Obtain your individual WireGuard .conf file, your lab Linux username/password
and the support contact. Each device needs its own assigned VPN address and key.
Do not share or reuse the lab's configuration or another student's configuration.

    Lab WireGuard VPN IP: 10.8.0.100
    Linux username: NameLastname (example: JavierPina)
    Initial Linux password: namelastname (example: javierpina)
    Administrator/support contact: mwestermeyer@udec.cl
    GPU schedule: _____________________________________

WireGuard connects to the public server at 152.74.19.95:10275/UDP using the
Endpoint in your assigned profile. X2Go and SFTP connect to 10.8.0.100:22 inside
the VPN. Your own student Address must be unique: do not assign yourself
10.8.0.100, which belongs exclusively to the GPU PC.

Your profile's AllowedIPs must include 10.8.0.100/32 or a containing route such
as 10.8.0.0/24. The administrator supplies this setting; do not replace your
student profile with the GPU PC's profile.

WireGuard uses the key in your profile to authenticate the VPN; X2Go uses your
Linux username/password. Usernames use NameLastname without spaces, preserving
the capital letters (JavierPina). The default initial password is always the same
username in lowercase (javierpina). Type the username with its exact capitalization
in SSH, X2Go and SFTP. Existing accounts keep their current username and password;
if your password has been changed, use the current password.

2. INSTALL THE CLIENT APPLICATIONS
----------------------------------
Install WireGuard for your operating system from:
    https://www.wireguard.com/install/
Use an SSH client on your computer for the recommended terminal access.
To use the available graphical desktop, install X2Go Client using:
    https://wiki.x2go.org/doku.php/doc:installation:x2goclient
On macOS follow X2Go's XQuartz requirements before connecting.

On Ubuntu/Debian, on YOUR computer:
    sudo apt update
    sudo apt install wireguard-tools openssh-client

For optional graphical access, also install:
    sudo apt install x2goclient

If the assigned profile contains DNS settings, ask your administrator which
resolver integration or network-manager client to use on your Linux system.
Do not run server installation scripts on your own computer.

3. CONNECT WIREGUARD
--------------------
On Windows/macOS, open WireGuard, import your OWN assigned .conf file as a
new tunnel and activate it. Follow the administrator's instructions for your
client version. Keep the profile private: it includes your VPN private key.

On Linux with an administrator-approved wg-quick profile:
    sudo wg-quick up /secure/path/student01.conf

The example filename is a placeholder; use your actual file. Its basename
becomes the Linux interface name and must be at most 15 characters. Keep
WireGuard connected while using SSH or X2Go. A client saying the interface is active
does not prove the public server is reachable: look for a recent handshake.
If the tunnel has no handshake or X2Go cannot reach the lab, contact support.

The intended class profiles route access to the lab through the VPN. Confirm
with the administrator if your profile also changes Internet or DNS routing.
Do not edit assigned addresses, keys or AllowedIPs without coordination.

4. CONNECT WITH SSH (RECOMMENDED)
---------------------------------
After activating WireGuard, open a terminal on your computer and run:

    ssh NameLastname@10.8.0.100

Replace NameLastname with your assigned username, preserving capitals. Example:

    ssh JavierPina@10.8.0.100

Enter your Linux password when prompted. The default initial password for
JavierPina is javierpina. Characters are not displayed while typing a password.
Use this terminal for code, commands and training in your assigned environment.
Run exit to close the SSH session when finished.

You can always open the XFCE desktop through X2Go using the next section when
you need graphical applications. SSH and X2Go access the same files/account.
For long-running training, save checkpoints and follow the lab's instructions
for keeping jobs running after disconnecting; a shell session alone is not a
job scheduler.

5. OPEN THE GRAPHICAL DESKTOP WITH X2GO
--------------------------------------
Open X2Go Client and create a new session. Enter:

    Session name: IDS Lab (or another name you recognize)
    Host:         10.8.0.100
    Login:        your assigned NameLastname (example: JavierPina)
    SSH port:     22
    Session type: XFCE

Select XFCE explicitly in the client's Session type selector, even if another
desktop type is preselected. This is a client setting for every saved session.

Use password authentication. Leave SSH key, proxy and automatic-login options
off unless the administrator specifically instructs you otherwise.

Save the session and open it.

Enter your Linux password when prompted. WireGuard does not use this Linux password.
The remote XFCE desktop should appear.

6. CHECK YOUR ACCOUNT AND GPU ACCESS
------------------------------------
In your SSH terminal, or a terminal inside the remote desktop, run:

    whoami
    echo "$HOME"
    nvidia-smi

The username should be yours and the home directory should normally be
/home/YOUR_USERNAME. If you see another person's account, stop and report it.

Follow the administrator's instructions to activate the course Python
environment. In that environment, you can check PyTorch with:

    python -c "import torch; print('CUDA available:', torch.cuda.is_available())"

If torch is missing, ask for the correct environment or the course's install
instructions. If CUDA is unavailable or nvidia-smi fails, contact the
administrator. Do not install or change NVIDIA drivers on the server.

Keep code, datasets and outputs in your own home directory or the shared
course location assigned to you. Do not use sudo on the server. Install
Python packages only in your own or the course-approved virtual environment.

The GPU is shared. Follow the booking rules, check current usage with
nvidia-smi, and ask before starting a large job. An idle-looking GPU is not
automatically permission to use all available memory. Stop only your own jobs.

7. TRANSFER FILES
-----------------
If you need to copy files, use an SFTP client with:

    Protocol: SFTP
    Host:     10.8.0.100
    Port:     22
    Username: your NameLastname, preserving capitalization
    Password: your Linux password

On a computer with the scp command, an example upload is:

    scp training.py YOUR_USERNAME@10.8.0.100:~/

Replace YOUR_USERNAME with your assigned Linux username. Run this
upload command on your own computer, where training.py is stored. WireGuard
must be connected. Do not send the whole class your password to share files.

8. FINISH OR RESUME YOUR SESSION
--------------------------------
Save your work before disconnecting. Use X2Go's Suspend option if you intend
to resume the same desktop. Suspending a desktop does not stop training or
release GPU memory; stop your jobs first if your allocated time has ended.

Use the desktop's Log Out option or X2Go's Terminate session option when you
are finished and want to close that desktop and its applications. A dropped
connection is not a guarantee that a training job stopped, or that it will
survive a reboot. Save model checkpoints and follow the course's instructions
for long-running jobs.

To reconnect, connect WireGuard first, then open the saved X2Go session. Resume
your existing desktop when offered instead of creating unnecessary sessions.

To stop a Linux wg-quick tunnel when finished:
    sudo wg-quick down /secure/path/student01.conf
On Windows/macOS use the WireGuard client's deactivate action. Disconnecting
the VPN does not guarantee that server-side training jobs have stopped.

To change your Linux password, run passwd in the remote terminal and follow
its prompts. This changes only the Linux password, not the keys in your WireGuard profile.

9. IF SOMETHING GOES WRONG
--------------------------
Connection timeout:
  Confirm your Internet connection, that WireGuard has a recent handshake, that you
  imported your own profile, and that the X2Go host is 10.8.0.100.
  Ask whether the server is online and your access is still active.

Incorrect password / authentication failure:
  Use your exact NameLastname username (JavierPina, not javierpina) and the
  lowercase initial password (javierpina), unless changed. Check keyboard layout
  and Caps Lock. Ask the administrator for a reset if needed; do not send
  passwords in a troubleshooting message.

Black screen or desktop does not start:
  Confirm the session type is XFCE. On macOS, check the XQuartz setup. Report
  the error rather than repeatedly creating more sessions.

CUDA unavailable / out of GPU memory:
  Confirm the selected Python environment. Ask about other scheduled jobs.
  Reduce your workload if appropriate; never terminate another student's job.

Slow display:
  Try a smaller desktop resolution and a stable connection. The connection
  passes through the public VPN hub; slow display does not by itself mean slow GPU training.

When contacting support, include your Linux username, your operating system,
the approximate time, the step that failed, and the exact error text. Do not
include passwords, private keys or invitation links in a public report.
